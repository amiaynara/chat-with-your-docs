# Client Brief

## Option 1: Chat With Your Doc

Build a system that answers questions about content from a document collection (PDFs, text files, or any format you choose). Classic RAG use-case.

## What to Submit

1. GitHub repo with your code
2. README.md with:
   - Quick setup instructions
   - Architecture overview
   - What would be required to productionise the solution and deploy it on a hyper-scaler (AWS / GCP / Azure / Cloudflare)
   - RAG/LLM approach & decisions: LLM, embedding model, vector database, orchestration framework, prompt & context management, guardrails, quality, observability
   - Key technical decisions and why
   - Engineering standards followed (and any skipped)
   - How AI tools were used during development
   - What would be done differently with more time
3. Screenshots of the application; a short video is a bonus

## What They're Looking For

- Tech stack that could be productionised
- Working Q&A over documents using RAG or a similar approach
- Creativity in UI/UX and product innovation
- Engineering excellence: clean, readable, well-structured, ideally containerised and observable
- Demonstrable AI-assisted development

## Tip

A basic working version with great engineering is preferred over a complex broken one.

Document edge cases that are not handled rather than hiding them.

A solid, well-engineered basic solution is valued more than an over-engineered complex one.
