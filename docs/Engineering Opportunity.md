# Engineering Opportunity

This assignment is an opportunity to demonstrate how I approach an ambiguous AI application as a senior engineer, from problem discovery through implementation and evaluation.

## What I Want to Demonstrate

I want the project to show that I can:

- clarify an open-ended requirement before committing to a solution
- define sensible scope, assumptions, and success criteria
- evaluate architectural and technology alternatives and make deliberate trade-offs
- understand the RAG pipeline end to end, rather than simply integrating a framework
- build a reliable working version incrementally through vertical slices
- design for maintainability, testability, quality, and observability
- distinguish what is necessary for this assignment from what would be required in production
- consciously defer production-only complexity and explain why
- identify important edge cases, failure modes, and limitations
- make the system and its decisions easy for another engineer to understand

## Initial Technology Direction

I will work within technologies that reflect my existing engineering experience:

- React + TypeScript for the frontend
- Python for the backend
- AWS as the primary production/cloud reference

The final choices within this stack—frameworks, databases, vector store, LLM, embedding model, orchestration approach, storage, etc.—should still be evaluated and justified rather than assumed.

## AI-Assisted Development

AI tools and agents will be treated as part of the engineering workflow, not simply as code generators.

I want to demonstrate a workflow covering:

**discovery → requirements → architecture → task decomposition → implementation → testing → review → refinement**

Agents should work from persistent project context such as requirements, architecture, decisions, interfaces, and acceptance criteria rather than repeatedly starting from zero.

I remain responsible for the requirements, architectural decisions, review, and final result.

## Standard

I am not trying to build the most sophisticated RAG system possible.

I am trying to build a **small, working, credible system** that demonstrates strong engineering judgement, sensible trade-offs, and a disciplined AI-assisted development process.
